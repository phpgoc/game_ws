# 沈阳麻将编排牌山验收

`e2e-wall` 构建可选读取 `SHENYANG_MAHJONG_E2E_WALL=dual-rob-gang`，仅在
首局、庄家为座位 0 时使用完整的 136 张编排牌山。每种牌恰好四张，仍由正常发牌和
WebSocket handler 执行所有动作。客户端不能提交手牌、窗口或结算结果。

默认构建不包含该模块，也不读取这个环境变量；缺省、未知名称、后续局或其他庄家均使用
原有洗牌逻辑。该配置不是部署必填项。编排牌山的 `last_wall_seed` 为 `None`，不能将它
描述成某个随机种子的输出。`e2e-wall` 保留正常计时：响应 5 秒、出牌 20 秒、默认
结算等待 5 秒。既有 `e2e-fixture` 包含该特性，仍保留响应 10 秒、其他等待 1 秒的
加速语义；需要观察多页面恢复和后续出牌的测试应单独启用 `e2e-wall`。

启用公开房间设置 `allow_first_chi=0` 后，四个真实客户端执行：

1. 庄家弃 37，座位 1 摸弃 34，座位 2 摸 32 后弃 3。
2. 座位 3 碰 3，座位 0/1 放弃当前胡牌；座位 3 弃 31。
3. 座位 0/1/2 分别摸弃 33/34/32，座位 3 摸到第四张 3 后加杠。
4. 座位 0/1 同时获得合法抢杠胡选项；座位 1 先胡并重连，座位 0 更新 PWA 后再胡。

## 集成测试的监听就绪

修改结果（2026-09-11，第 60 包验证前置修复）：`integration_flow` 原先反复绑定测试
端口来判断服务是否启动，探测会与服务抢占监听端口；默认并发和串行重跑均出现

修改建议：新增集成测试沿用 ready 信号，不能用占用端口推断服务可连接。此修复只处理
验证环境启动竞争；牌局请求和超时之间的状态竞争另行修复、验证并提交。

## 请求与超时的状态竞争

修改结果（2026-09-11，第 60 包）：后台循环原先读取已超时座位后释放牌局锁，等待
房间锁查询会员资格，再依据旧判断执行超时动作。若最后一个响应已结算或完成加杠补牌，
旧任务仍可能对新回合自动出牌或关闭新窗口。现在取得同一房间和牌局锁后，确认仍处于
Play、未暂停/停止且倒计时为零，再读取当前共享会员标记并同步完成超时动作；确认与
执行之间没有 await。普通 tick 也不递减暂停或已离开 Play 的状态。

新增五组回归覆盖最后响应先完成、超时先完成后迟到 HU/PASS、零秒部分胡后另一方超时、
新窗口/暂停/停止/新局使旧超时失效，以及普通出牌超时读取当前会员资格。缺少执行前
校验时三组失败，修复后五组通过。请求先完成时保留其结算/补牌结果；超时先完成时拒绝
迟到请求，不重复结算、补牌或标记抢牌者暂离。保持现有“仍开放窗口中的请求与超时按
实际持锁处理顺序决定结果”语义，不把整数倒计时零改成独立的精确到毫秒的截止时间。

验证：默认构建 398 项单测、1 项能力测试和 4 项真实 WS 集成测试通过；`e2e-wall`
400 项单测通过；`official` 与 `e2e-fixture` 各五项定向回归通过；所改 Rust 文件格式
检查通过。`official` 集成测试编译另被已有二进制的 `runtime_common`/`tracing` 依赖
缺失阻止，未把它计为通过，当前补丁没有修改该二进制或依赖声明。

Web 正常计时的 `hu-expired`、`pending-expired` 和跨局重新发牌三条真实 PWA smoke
通过：分别保留一条 HU、只生成一次 GANG/DRAW，以及恢复下一局 14 张手牌并出牌至
13 张；旧请求重发均为零。材料在主仓库 `web/test-results/prepublish-stage60.eRmMrp/`，
不随 WS 提交。运行时不需要新增环境变量或更新主仓库 gitlink。

# 沈阳麻将编排牌山验收

`e2e-fixture` 构建可选读取 `SHENYANG_MAHJONG_E2E_WALL=dual-rob-gang`，仅在
首局、庄家为座位 0 时使用完整的 136 张编排牌山。每种牌恰好四张，仍由正常发牌和
WebSocket handler 执行所有动作。客户端不能提交手牌、窗口或结算结果。

默认构建不包含该模块，也不读取这个环境变量；缺省、未知名称、后续局或其他庄家均使用
原有洗牌逻辑。该配置不是部署必填项。编排牌山的 `last_wall_seed` 为 `None`，不能将它
描述成某个随机种子的输出。既有 E2E 计时与正式计时不变。

启用公开房间设置 `allow_first_chi=0` 后，四个真实客户端执行：

1. 庄家弃 37，座位 1 摸弃 34，座位 2 摸 32 后弃 3。
2. 座位 3 碰 3，座位 0/1 放弃当前胡牌；座位 3 弃 31。
3. 座位 0/1/2 分别摸弃 33/34/32，座位 3 摸到第四张 3 后加杠。
4. 座位 0/1 同时获得合法抢杠胡选项；座位 1 先胡并重连，座位 0 更新 PWA 后再胡。

修改结果（2026-09-11，第 56 包）：两项 Rust 测试验证完整牌山、两家合法胡牌牌型和
启用边界；默认构建的 17 项状态测试通过。Web 的 `test:prepublish:pwa-multi-rob-gang-update`
真实四人流程通过：已响应者重连没有选项/重发请求，剩余玩家仍能胡，最后按座位发出两条
HU 并双人结算。来源只扣一张手牌、保留原 PENG，牌河和牌墙不变，不补牌。
倒计时实际下降后再次通过：已响应者重连前后均为 7 秒，另一方 PWA 更新后剩 5 秒，
没有重新给满 10 秒。原随机种子的单响应方抢杠回归也通过。

修改建议：继续双响应方胡/过及自然过期组合。当前证据使用合法编排的完整牌山和本地
桌面 Chromium，不代表自然随机对局、移动设备或正式发布观察已验收。
